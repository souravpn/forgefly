## Decisions

- **Image generation via templated SVG→PNG render (not AI diffusion) for the default "Generate with AI" path** — chosen over calling an image-gen API for the primary flow because the reference design (PacUX example) is a precise structured layout (logo, stat, headline, footer) that diffusion models can't hit reliably; SVG+resvg is pixel-perfect, free, and instant. Built with plain SVG string templates (not satori) since only 2-3 fixed layouts are needed — avoids the extra JSX-layout-engine dependency.
- **Font loading via `cdn.jsdelivr.net/fontsource` at request time** — chosen over bundling a font file with the function, since Deno edge functions can fetch at cold start and this avoids binary assets in the repo. Verified locally with a Deno script before trusting it in prod.
- **`@resvg/resvg-wasm` over `@resvg/resvg-js`** — resvg-js needs native bindings not available in Supabase's Deno edge runtime; the WASM build works via `npm:` specifier (confirmed other functions already use `npm:` imports for Stripe/node-forge, so this pattern is supported).
- **New `social_post_targets` join table instead of a `platforms text[]` column** on `social_posts` — user explicitly chose this so each platform can have independent status (pending/published/skipped) since the publish workflow customizes per-platform.
- **Kept URL `/dashboard/social`, renamed only the visible label to "Promotions"** — avoids breaking the Instagram OAuth redirect URI and any bookmarked links; user confirmed this tradeoff explicitly.
- **Manual "Generate with AI" has no daily limit; only automatic/proactive daily generation (not yet built) should be capped at once/day** — original design wrongly conflated the two via a DB unique index on `(business_id, featured_date) WHERE is_featured`; corrected per explicit user feedback mid-session (migration 00045 drops that index).
- **Second "Generate with OpenAI" button added alongside the templated one, not replacing it** — user wants both available now: cheap/free templated render as default, true gpt-image-1 diffusion as an explicit opt-in with its real cost shown. Noted in code as a future agency-tier gate (not yet implemented — currently available to anyone with Promotions access, which is already agency-gated).

## Bugs / issues surfaced

1. **Stat text overflow in templated card** — symptom: AI-generated `stat` field like "40% faster" (longer than expected) overflowed the fixed 220px font size off the card edge. Root cause: hardcoded font size assumed short stats. Fixed: `statFontSize()` now scales font size to fit width, plus prompt now asks for ≤8 chars and code clamps to 12. **Status: fixed, verified live.**
2. **Duplicate-publish race on regenerate** — symptom: clicking "Generate with AI" after today's Featured promo was already published re-served the same (now-published) post as if still editable, which would have re-published a duplicate Instagram post if approved again. Root cause: existing-post lookup in `generate-promotion` matched on `featured_date` regardless of `status`. Fixed in two passes: first added a 409 guard requiring `status='draft'`, then per user feedback the daily-limit concept itself was wrong (see Decisions) — final fix drops the DB unique index (migration 00045) and only blocks when an *unresolved* draft exists, regardless of date. **Status: fixed, verified live.**
3. **`OPENAI_API_KEY` secret not configured** — symptom: "Generate with OpenAI" failed with `Bearer undefined` → 401 from OpenAI. Root cause: despite CLAUDE.md documenting this secret as required, it was never actually set on the linked Supabase project (`supabase secrets list` confirmed absence). User added it themselves via CLI. **Status: fixed** — CLAUDE.md's secrets list may need updating since this project drifted from that doc.
4. **OpenAI billing hard limit** — after the key was added, OpenAI rejected with `billing_hard_limit_reached`. Account-side issue, not code. User resolved on their end. **Status: fixed.**
5. **AI usage not logged for Promotions calls** — symptom: user generated an image with OpenAI (cost $0.04) but it never appeared in Settings → AI History. Root cause: `generate-promotion` never called the `logUsage`/`ai_usage_log` pattern that `ai-gateway` uses for other AI features. Fixed: added a local `logUsage` helper logging both the Claude text call (real token counts, Haiku pricing) and the OpenAI image call (flat `$0.042` estimate for medium-quality 1024x1024) to `ai_usage_log`. **Status: fixed, verified live for the text-call path** (confirmed row appears in AI History UI); the image-call logging path uses the identical code path so wasn't re-verified with a second real charge, but should be checked next session if in doubt.
6. **routes.tsx / AppSidebar.tsx / SocialPage.tsx label reverted from "Promotions" back to "Social" multiple times during the session** — some external process (formatter/editor autosave, per system reminders) kept reformatting these files and reverting the label edits. Re-applied the "Promotions" label each time it was caught; final state should say "Promotions" in `routes.tsx` name field, `AppSidebar.tsx` `SOCIAL_ITEM.label`, and `config/navigation.ts` MORE_ITEMS social label — **worth double-checking these three at the start of next session**, since this pattern recurred unpredictably and may have reverted again after the session ended.
