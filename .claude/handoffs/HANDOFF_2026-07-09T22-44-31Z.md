## Decisions

- **OAuth redirect stays pointed at `/settings?tab=account`** even after the Connect UI moved to the Social page — re-registering redirect URIs in Meta's dashboard was already painful once, so Settings still completes the token exchange and then `navigate()`s to `/dashboard/social` afterward, rather than re-doing Meta config.
- **Instagram uses its own App ID/secret** (`INSTAGRAM_APP_ID`/`INSTAGRAM_APP_SECRET`), separate from the main Meta App ID (`META_APP_ID`) used for Facebook Login/WhatsApp — Instagram Login (`instagram.com/oauth/authorize`) rejects the parent Facebook App ID with "Invalid platform app". Meta's dashboard exposes a distinct "Instagram app ID" under the Instagram API setup page for this.
- **WhatsApp OAuth scope dropped `business_management`** — it's not granted on this app and was rejecting the whole scope list with "Invalid Scopes". Switched WABA discovery from `/me/businesses` → `owned_whatsapp_business_accounts` (needs `business_management`) to reading `granular_scopes` off `/debug_token` (Meta's documented embedded-signup approach, needs only `whatsapp_business_management`).
- **Instagram's OAuth redirect URI list requires HTTPS only** — unlike Facebook Login, Instagram Login has no localhost auto-allow exception and rejects `http://localhost:...` entries outright (silent save failure). Decision: test Instagram connect from the deployed prod site only; WhatsApp/Facebook Login still works from localhost.
- **"Public Portfolio" = `PortfolioPage.tsx` (`/dashboard/portfolio`)**, not `PublicPortfolioPage.tsx` (the actual `/p/:slug` visitor-facing render) — confirmed via the sidebar literally labeling that route "Public Portfolio". This resolved otherwise-fatal ambiguity in the Portal/Work move request.
- **Portal/Work tabs merged into PortfolioPage's existing tab set** rather than given a separate page — renamed its old preview-iframe tab from "portal" to "preview" (freeing the name) and added "sections" (labeled "Portal") and "work" tabs, reusing `slug`/`portfolioUrl` already derived there instead of duplicating BrandKitPage's `portfolioSlug` variable.
- **Business Information card removed entirely**; only "Business Description" survived, folded into the Public Identity card as optional. Service Type and Hourly Rate dropped from the UI per explicit user choice (unused anywhere else in the app, only ever set once at onboarding).
- **AI usage cycle is signup-anniversary-based, not calendar-month** — a user who signed up on the 21st sees "June 21 – July 20", computed by `getUsageCycle()` off `profile.created_at`, not `new Date(year, month, 1)`.

## Bugs / issues surfaced

- **`ReferenceError: upgradeModalOpen is not defined` crashed the Settings → AI History tab.** Root cause: a stray `<UpgradeModal>` was left inside the `AIHistoryTab` component (separate function scope) referencing state that only exists in the parent `SettingsPage`. This was also the actual cause of last session's parked "Manage plan button doesn't open modal" bug — the modal was rendering in the wrong tree entirely, not a Vite/HMR issue as suspected then. **Fixed** — moved the modal render to `SettingsPage`'s own return.
- **Meta dashboard: OAuth redirect URI silently failed to save** when both an `https://` and a `http://localhost` entry were listed together for Facebook Login. Root cause: "Enforce HTTPS" was locked on for that Login product, and the non-HTTPS localhost entry invalidated the whole list with no visible error (confirmed via incognito reload showing the field empty despite an apparent successful save). **Fixed** — removed the localhost entry; it's auto-allowed by Meta in Development Mode without needing to be listed.
- **Instagram OAuth: "Invalid platform app"** — using the main Meta App ID as `client_id` for Instagram Login. **Fixed**, see Decisions.
- **Instagram OAuth: "Invalid redirect_uri"** even after fixing the App ID — Instagram Login's redirect URI list rejects `http://localhost` entries outright (no dev-mode exception). **Workaround in place**: test Instagram connect from prod only; not a code bug.
- **WhatsApp OAuth: "Invalid Scopes: business_management"**. **Fixed**, see Decisions (switched to `/debug_token` granular_scopes).
- **`.env` edit appeared in the user's editor but wasn't actually saved to disk** — caused a `client_id=undefined` OAuth URL that persisted across multiple dev-server restarts until diagnosed by directly reading the file via the agent's own filesystem access (same file, confirmed unsaved). Not a code bug, but the debugging path (comparing editor state vs. actual file content) is worth remembering if `import.meta.env` values seem to not update.
