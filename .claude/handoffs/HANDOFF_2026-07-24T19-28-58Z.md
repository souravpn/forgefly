## Decisions

- **Pinterest ships as a placeholder only** (`comingSoon`, no OAuth) — explicitly the same treatment as X/LinkedIn today. Real Pinterest OAuth is deferred; needs a Pinterest Developer app (client ID/secret) the user hasn't provisioned yet.
- **"Request a platform" card is DB-only for now, no email notification.** Chose not to add a new `send-email` template/type for this to avoid scope creep — the founder can query the `platform_requests` table directly. Revisit if request volume makes that annoying.
- **Market research pipeline (next phase, not started):** scoped as an async background job triggered post-generate, using real web-search grounding (doesn't exist anywhere in the codebase today — `research-company` only fetches one known URL via `safeFetch`, it doesn't search). Output gets parsed into a fixed allow-list of atomic item types (`outreach_draft`, `channel_signup_suggestion`, `pricing_note`, `positioning_insight`), each tagged `actionable` or `fyi`. Actionable items go through a swipe-to-queue UI, but **swipe-approve only queues the draft — it does not send.** Real sends to venues/planners still require the existing propose/execute two-phase confirm, same as every other Freeda action, because these are cold outreach to third parties who've never heard of the freelancer (materially different risk than messaging the freelancer's own existing clients). Cheap-agent fan-out (parallel Haiku calls, one per draft) is the right cost optimization for the drafting step.
- Full architecture diagram published as an Artifact: https://claude.ai/code/artifact/db177b36-b0b2-41d2-b952-4d306629237d — walks seed → trigger → background synthesis → status polling (reusing the `check-video-render` pattern) → item breakdown → parallel fan-out → swipe queue / FYI feed split → future Market Research tab.
