## Session goal

Build "Freeda" — a single AI-assistant surface for Forgefly (a freelancer business OS) that lets users update business data, ask questions about their business, and message clients, all from one natural-language input — replacing the previous two separate surfaces ("Upgrade my Business" top bar + "AI Copilot" chat panel). Harden it through live testing (numerous real bugs, including two data-loss bugs, found and fixed). Then: remove a stale Social private-beta gate, and scope (but not yet build) Instagram Reels support.

## Decisions

- **Single surface lives in the right panel**, not a top bar — per Sourav's sketch: toggled via "Ask Freeda" in `AppSidebar`, closeable, resizable, keeps the existing scrolling chat history (rejected single-shot/inline-replace design from an earlier mockup — least regression from what `AICopilot` already had).
- **5-bucket intent router** (`update` / `query` / `action` / `support` / `off_topic`) via a small, cheap Haiku call in `ai-gateway`, separate from the heavier extract/chat calls — keeps routing fast and avoids the earlier token-truncation failure mode.
- **KPI/query answers matched against a fixed catalog** (~10 entries mirroring exactly what's on the Dashboard) rather than a general query-builder — chosen as the pragmatic v1; a real constrained query-builder was explicitly deferred (cross-tenant data exposure risk if built carelessly, needs its own design pass).
- **Backend returns only a matched KPI id, never a computed value** — frontend fetches the live number via the same `loadOverviewData()` the Dashboard itself uses, so a number Freeda states can never drift from what's on screen.
- **Action recipients always require naming or explicit selection, never a guessed subset** — Sourav's explicit call when "message 3 of my clients" ambiguity came up. Modeled as a fixed allow-listed selector (`named` / `filter` / `all` / `ambiguous`) — the model picks a mode + parameter values, app code runs the actual safe query; `ambiguous` always surfaces a picker instead of guessing.
- **Array merges (services/contacts/pipeline/invoices) always upsert-by-name now**, regardless of the classifier's `prompt_type` guess — after two real data-loss incidents where a classifier miss caused wholesale replacement of existing business data. Merging is now gated on "does prior data exist," never on a classifier label.
- **Action proposal and action execution are two separate, separately-reviewed steps** — proposal is read-only (recipients + draft), execution requires explicit user confirmation of the exact list/text, per the AI-to-database security boundary in CLAUDE.md.
- **`{payment_link}` left blank in the general send path** rather than built — resolving a real portal link for named/all/ambiguous recipients needs its own contact+engagement+token resolution; scoped out rather than half-build it. Only affects sends where the draft happens to reference a payment link outside the invoice-filter flow.
- **Deletion (remove client/service) intentionally not built** — routes to `support`, which now explains honestly that it isn't automatable yet and offers a "Take me there" button, instead of the old misleading "try rephrasing?".
- **Chat/action navigation buttons no longer auto-fire** — changed to a "Take me there" button the user must click, after observing an auto-navigate mid-read felt jarring (and was sometimes wrong — see bare-path bug below).
- **Social private-beta gate removed entirely** (`social_beta_enabled` flag) rather than re-enabled per-account — Sourav confirmed Instagram/WhatsApp testing is far enough along; deleted the gating code in `SocialPage.tsx` rather than just flipping the flag, since the flag was never written anywhere in app code (manual DB-only toggle) and had no future purpose once removed. Social is now open to all agency-tier users (the underlying agency-tier gate is untouched).
- **Instagram Reels: auto-generate a short video from the existing promo image**, chosen over "user uploads their own clip" — Sourav wants "both post and reel" as the *default* behavior, which only works if a video is produced automatically with no extra step. Confirmed real Instagram Graph API constraint first: Reels require an actual video file (`media_type: REELS` + `video_url`) — the current PNG output cannot be reused directly, and no video-generation infra exists in this codebase today (checked; nothing found).
- **Video vendor: Shotstack, pay-as-you-go** ($0.30/min, ~$0.025 per 5-second clip, no monthly commitment, 10 free credits ≈120 test clips) — recommended over Creatomate (similar per-clip cost but only available via a $54/mo+ subscription) and Cloudinary (video not on free tier, cheapest video-capable plan is $89/mo, clearly built for higher-volume/broader use). Matches current low volume (at most one featured promotion per business per day). **Not yet implemented** — pricing/vendor decision made, build not started.

## Bugs / issues surfaced

1. **Wrong navigation path** — "show my clients" navigated to bare `/clients`, hit the app's catch-all redirect back to `/`. Root cause: chat system prompt never specified the `/dashboard` prefix. **Fixed**: prompt now lists exact valid paths; frontend also defensively normalizes any path the model still gets wrong.
2. **$0 revenue shown despite real paid invoices** — Root cause: relied on PostgREST's embedded aggregate syntax (`amount.sum()` in `.select()`), which silently failed (not guaranteed enabled on this project) and the error was never checked. **Fixed**: sum client-side in the edge function instead.
3. **Markdown not rendering** (literal `**asterisks**`/lists shown as raw text). **Fixed**: added `react-markdown` with compact custom component styling for assistant messages only.
4. **Garbled raw-JSON dump in chat**, missing navigation, generic suggestions — Root cause: `handleChat`'s JSON-parse-failure fallback set the visible message to the entire raw unparsed model output (including literal `\n` escape sequences). **Fixed**: bumped token budget 600→1000, reinforced "JSON only" instruction at the end of the prompt (recency-weighted), fallback now regex-extracts just the `message` field via JSON's own string parser instead of dumping raw text.
5. **Data loss: adding one service wiped every other stored service.** Two-layered root cause: (a) `deepMerge`'s array-append logic was gated behind `additive && …`, so any classifier `prompt_type` other than exactly `'additive'`/`'revision'` fell back to wholesale array replacement; (b) deeper — `handleExtract`'s `finalData` computation skipped calling `deepMerge` *at all* when `isDiff` was false, using the raw (diff-only) extraction output directly. **Fixed both layers**: merging now happens whenever prior data exists, and array merges always upsert-by-name regardless of any classifier flag. **Status: fixed and confirmed by live retest.**
6. **Compound requests (real update + unsupported ask bundled) got downgraded to `support`** — e.g. "add a client + email them a proposal" only got explained, not applied. Root cause: single-bucket-per-message router hedges toward `support` when part of a message is unsupported. **Status: partially fixed** — heuristic bias added (a genuine update instruction wins even when bundled with something unsupported). True multi-intent decomposition is **not built** — flagged as an open architectural limitation.
7. **`action` bucket over-triggering** on "create a proposal" / "generate an invoice" — these hit the one hardcoded action handler (pending-invoice reminders), producing the same wrong "no pending invoices" answer regardless of what was asked. **Fixed**: narrowed/clarified the router's bucket boundaries with explicit examples.
8. **Uncaught exception crashing the entire request** (raw 500, cryptic "Unexpected token" error) — Root cause: `extractSection`'s retry-after-parse-failure path had a second, unguarded `JSON.parse` call that threw when the model responded conversationally instead of JSON (triggered by e.g. "send them a message" embedded in an otherwise-valid update prompt). **Fixed**: wrapped the retry parse too; degrades to an empty section instead of crashing the whole request.
9. **"Remove/delete a client" gave a misleading "try rephrasing?"** — not a bug exactly, an unbuilt capability (no deletion semantics anywhere in the extraction schema). **Fixed the UX**: now routes to `support`, which explains honestly that deletion isn't automatable yet + offers a "Take me there" button.
10. **"How many invoices are due" matched the wrong KPI** (`upcoming` — time-windowed, mixed-category) giving a misleading "nothing on the horizon." **Fixed**: tightened `upcoming`'s matching description to exclude general invoice-count questions, which now fall through to the freeform chat answer (has an accurate count in context).
11. **Action-execution send failing with Meta error `#131030 Recipient phone number not in allowed list`.** Root cause: WhatsApp Business number still in Meta sandbox/dev mode, which restricts sends to explicitly allow-listed test recipients — a Meta account configuration issue, not a code bug. **Resolved** by Sourav adding test numbers in Meta App Dashboard → WhatsApp → API Setup. **Confirmed working end-to-end by live test.**
12. **`/social` page unexpectedly showing a "private beta" lock screen.** Initially suspected to be fallout from bug #5 (the data-loss bug could plausibly have wiped the `extracted_data.settings.social_beta_enabled` flag, since it lived in the same JSON blob that was getting wholesale-replaced). Investigated via `git log -S` and found the actual cause: a deliberate gate added in an earlier session (commit `b830b273`, "Restrict Social page to a per-business beta flag on top of agency tier") to hide Instagram/WhatsApp publishing while testing against a personal Meta developer account. **Not a bug** — resolved by Sourav's explicit decision to remove the gate now that testing is further along (see Decisions).

Earlier in the same session (before the Freeda work): fixed a Dashboard-triggered layout bug in `MessagesPage.tsx` (hardcoded `SHELL_HEIGHT` constant drifted stale after a chrome change, causing the client list to visually "jump" when opening a thread — replaced with dynamically-measured available height); built WhatsApp invoice-payment-link sending in `InvoicesPage.tsx`; deleted an unused legacy OpenAI-based `ai-copilot` edge function and corrected CLAUDE.md (had documented it as OpenAI-powered; the real, active copilot has always used Claude via `ai-gateway`).
