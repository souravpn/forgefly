## Session goal
Build Instagram Reels generation for Forgefly's Social/Promotions feature: turn the AI-generated (gpt-image) promo photo into a short Ken Burns pan/zoom video via Shotstack, with a business-name pill overlay, verify it end-to-end on Instagram, then extend to Facebook (not started).

## Decisions
- Reel generation is scoped only to the `mode: 'featured_openai'` (gpt-image) path in `generate-promotion` — the resvg-template path (`mode: 'featured'`) stays stills-only.
- Every `featured_openai` generation produces both the still and the Reel automatically (not an opt-in extra step), per early user preference.
- Frontend polls `check-video-render` every 4s rather than using a Shotstack webhook — simpler, matches the existing Instagram container-status polling pattern already in the codebase.
- The business-name pill is visual-only, burned into the video via a Shotstack `html` asset — no attempt at a real clickable overlay, since video platforms don't support that. The actual link stays in the caption's "link in bio" CTA.
- Switched the image model from `gpt-image-1` to `gpt-image-2`: better output quality (user's own comparison) and correctly costs $0.053/image (medium, 1024x1024) confirmed against OpenAI's official pricing docs — the old `OPENAI_IMAGE_COST_USD` constant (0.042) was wrong for the model in use.
- Changed the gpt-image prompt from "text poster with baked-in headline/stat" to "illustrate the caption, no text at all" — gpt-image models render baked-in text unreliably (blurry/garbled), and a text-free illustration also gives the Ken Burns effect something visually interesting to pan across.
- Reel canvas uses `fit: 'contain'` (preserves the original square photo's aspect ratio) instead of `cover` (was stretching/cropping it to fill 1080x1920), with `hero-bg.png` (from `/public`) as a full-bleed backdrop behind the letterboxed photo. Chosen over `CTA-bg.png` (has a baked-in wordmark) and `upgrade-os-background.png` (wrong aspect ratio).
- Publish behavior: rejected an either/or Photo vs. Reel toggle at publish time in favor of always publishing **both** sequentially (photo then Reel) as two independent Instagram posts when a Reel is ready — simpler mental model, matches what the user actually wants ("post both, one after the other").
- Introduced `social_post_targets.platform = 'instagram_reel'` as a new (unchecklisted) value to track the Reel publish as its own row, separate from the photo's `'instagram'` row — avoids the two publishes clobbering each other's `platform_post_id`.
- Shotstack is on the **sandbox** endpoint (`/edit/stage/render`) with a sandbox key deliberately, for free/watermarked testing before committing to a paid production key.
- Every Supabase deploy/prod-DB read this session was gated behind explicit user confirmation (project is "Forgefly-prod") — establish this as the standing pattern, not a one-off.

## Bugs / issues surfaced

2. **Instagram account `forgeflydev` restricted** ("can't share links," flagged for fraud/scams community standards) — likely triggered by repeated API-published promotional posts with repetitive "link in bio" CTA phrasing from a low-history business account. Status: **open**, restriction runs until ~2026-08-13 unless a review is requested and approved. User wants to hold off on further live IG publish testing for a while after this session.
3. **`use_video` always `false` on publish** even after selecting "Reel" on the card — root cause: `PromotionCard`'s preview toggle and `PublishWorkflowModal`'s publish toggle were two disconnected state variables. Superseded by the "always publish both" redesign (the modal toggle was removed entirely). Status: fixed.
4. **Reel publish failing with "Post must be approved before publishing"** — root cause: the photo leg's publish flips `social_posts.status` from `'approved'` to `'published'`, so the second (Reel) leg's approval-gate check then rejected it. Fixed by allowing `status === 'published'` through the gate too. Status: fixed.
5. **Generic "Edge Function returned a non-2xx status code" errors masking real failures** — supabase-js collapses all non-2xx edge function responses into one generic message. Fixed via `unwrapFunctionError()` in `promotionService.ts`, which parses the actual JSON `{error}` body out of `FunctionsHttpError.context`. Status: fixed.
6. **Top-level `social_posts.platform_post_id`/`published_at` overwritten by whichever leg (photo/Reel) published second** — fixed by only writing those columns when `post.status !== 'published'` yet (i.e. only on the first leg); per-artifact detail was already correctly isolated via `social_post_targets`. Status: fixed.
