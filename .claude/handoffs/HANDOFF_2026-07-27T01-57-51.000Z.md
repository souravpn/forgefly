## Decisions

- **Search-grounding: Perplexity Sonar API (not Anthropic's web-search tool, not Brave/Serper, not Perplexity's Agent API).** Sonar gives one fixed-cost call per research angle (search + synthesized answer with citations) versus Agent API's per-tool-invocation billing (`web_search` $0.0025, `people_search`/`finance_search` $0.005, `sandbox` $0.03/session) which is open-ended since the agent decides how many tool calls to make. Search API alone would just return raw snippets requiring the same Claude synthesis step anyway, so it added no value over Sonar. Realistic cost modeled at ~$0.07/business/run (3 Sonar calls at Medium context + 1 Sonnet synthesis + ~7 Haiku fan-out drafts) — the calculator's $0.007 headline figure is a Low-context, single-call floor, not realistic.
- **Trigger fires once per business, fire-and-forget, no manual re-run yet.** Explicitly deferred a cooldown/rate-limit column since re-runs aren't built; `market_research.trigger_source` (`generate_call` | `manual`) already anticipates it.
- **`kind` (actionable/fyi) is derived server-side from `item_type`, never trusted from the model's own output** — a fixed mapping (`outreach_draft`/`channel_signup_suggestion` = actionable, `pricing_note`/`positioning_insight` = fyi) enforced in the edge function, per the AI-to-DB security boundary.
- **Swipe-to-decide (drag gesture) is outreach_draft-only disabled, channel_signup_suggestion-only enabled.** Approving an outreach draft now triggers a real email send — a stray drag must never fire that — so that card is button-only. Channel suggestions have no real send, just a status flip, so drag-to-decide is safe there.
- **Approve & Send on outreach_draft also creates a pipeline lead, stage fixed to `'Proposal Sent'` (user's explicit call, not `'Prospect'`)** — reasoning: an actual message was sent, so "Proposal Sent" better reflects reality than a colder "Prospect" stage. Idempotent by contact email via `addLeadToPipeline()` in `MarketResearchPage.tsx`.
- **channel_signup_suggestion's "Approve" now opens the channel's URL in a new tab** (when one was found) instead of silently flipping a status nobody read — explicitly scoped as "the small fix now," not a full checklist/reminder system (that's still open, see Open Questions).
- **Onboarding's fake demo leads: fixed by stripping at save-time, not by touching the preview.** `stripDummyPipelineLeads()` clears `extracted_data.pipeline.leads` in both `AuthCallbackPage.tsx`'s `saveBusiness()` and `useCurrentBusiness.ts`'s insert branch, right before the business row is persisted. The `/preview` marketing page and the onboarding preview UI still intentionally show the fake examples — only the real save was ever the problem.
- **`send-email`'s existing `client_message` type reused for outreach sends** — no new email template needed; same generic freeform-body email type already used for proposal follow-ups.
